# Accessibility (axe) CI gate

Issue: #26  
Runner: Storybook **Vitest** project `a11y` + `@storybook/addon-a11y` (axe-core).

## Commands

```bash
# Install Chromium once (local / CI)
pnpm --filter @pack-challenge/ui exec playwright install chromium

# Run axe against stories tagged `a11y-gate`
pnpm a11y
```

CI job **`a11y`** (`.github/workflows/pr-gate.yml`) runs the same script and should be required on `main`.

## How atom (+ later) stories join the gate

1. Co-locate stories under `packages/ui/src/components/atoms/<name>/` or `molecules/<name>/` (etc.).
2. Add Storybook tag **`a11y-gate`** (Vitest project include filter).
3. Set **`parameters.a11y.test = 'error'`** so axe violations fail CI (not `'todo'`).
4. Add co-located **`*.a11y.spec.ts`** (jsdom + `vitest-axe`); `pnpm test` runs project `a11y-specs`.

Example (`defineMeta`):

```ts
const { Story } = defineMeta({
	title: 'Atoms/Input',
	component: Input,
	tags: ['a11y-gate', 'autodocs'],
	parameters: {
		a11y: { test: 'error' }
	}
});
```

Default preview stays `a11y.test: 'todo'` so particles / scaffolding do not fail the gate until opted in.
